### What moved
- `APARTMENTS` array → `lib/apartments/data.ts`. The per-apartment meta
  (`valueScore` / `luxuryScore` / `funTags` / `rankBoost`) is now **folded onto
  each Apartment object** (the old `APT_META` + `RANK_BOOST` maps are gone).
  Adding an apartment is now one object edit. Fold was done by a one-shot
  transform script (deleted after) so the 30 objects' verbatim copy/descriptions/
  reddit seeds are byte-preserved; only 3–4 fields inserted after `shuttleMinutes`.
- `VALUE_LABELS`, `LUXURY_STARS`, `STATIC_RANKING`, and the filter option
  constants → `lib/apartments/data.ts`.
- `VoteTalliesProvider` / `VoteButtons` / `DynamicLeaderboard` / `CommentsSection`
  (plus a 5th extraction, `ApartmentCard`, needed to get the page under 450) →
  `app/apartments/_components/`.

### Ranking-parity evidence
`STATIC_RANKING` is still `rankBoost(default 0) + Σ(reddit-seed scores)` sorted
desc over the array (stable sort). The `rankBoost` values fold identically
(beaudry 1600, 888 1000, alina 900, aven 600, 1133 150; the two former `0`
entries are just omitted → default 0 → same score). The computed order is
**pinned byte-for-byte** in `lib/apartments/data.test.ts`
(`EXPECTED_RANKING_IDS`, 30 ids, incl. the thea-dtla-before-nari-koreatown tie at
1960). Data-integrity test also asserts: 30 apartments, unique ids, every
apartment carries the folded fields, STATIC_RANKING covers only-real ids, and
each score == rankBoost + reddit sum. All 6 assertions pass.

Consumer parity: the filter that read `APT_META[apt.id]?.valueScore ?? 2` now
reads `apt.valueScore`; because every apartment has meta, this is identical. The
value/luxury badge block was previously gated on `APT_META[apt.id]` (always
truthy for all 30) so it now renders unconditionally — same markup.

### Architecture
- `ResultsView`'s inline solver (`buildCombos` / `generateCombos` / `shuffleTied`
  / `backtrack` + dedup) is hoisted verbatim to `shared/schedule-solver.ts` as a
  pure `buildSchedules(...)`. It imports **only** shared types + shared primitives
  — never `lib/` (respects the shared→lib direction ban).
- The conflict/overlap helpers and the section rules moved to
  `shared/schedule-conflicts.ts` and `shared/section-rules.ts`;
  `lib/course-planner/conflicts.ts` and `rules.ts` are now thin re-export shims so
  every existing site consumer keeps its import path.
- `ResultsView` imports the solver (aliased `solveSchedules` to avoid colliding
  with its local `buildSchedules` orchestrator callback). Network + RMP fetching
  stays in the component; only the pure solve is hoisted. `courseGroups` is
  returned so the swap UI still works — and the swap `any` casts / eslint-disables
  were dropped now that combos are typed (`SectionCombo` / `TimeSlot`).

### Solver parity notes
- The default `shuffleTiedWith(arr, random)` is byte-identical to the original
  inline `shuffleTied`; `random` defaults to `Math.random` and `now` defaults to
  `Date.now`, so ResultsView's production ordering is unchanged. Both inline
  conflict checks were replaced by `slotsConflict(a,b)` whose body is the exact
  same `day === && startMin < endMin && startMin < endMin` predicate.
- `colorCount` (default 8, ResultsView passes `COURSE_COLORS.length`) replaces the
  `% COURSE_COLORS.length` literal; `maxResults`/`comboTimeoutMs` default to 5 /
  25000 as before.
- Unit tests pin: conflict exclusion (overlapping-only → 0 schedules),
  non-conflicting placement, **back-to-back allowed** (10–11 + 11–12 touch, no
  conflict, both placed), blocked-days, RMP ranking + courseGroups exposure,
  determinism under injected shuffle, GE `geTag`, and `shuffleTiedWith`
  determinism / 0.15 tie-window. 9 new tests, all green.

### Extension (SANCTIONED convergence)
`ScheduleOptimizer` deleted its own `buildCombos` / `optimizeSchedule` and now
calls the shared `buildSchedules` (adapting its `CourseGroup[]` → `selections` +
`selectionMap`, empty `rmpCache` → neutral scoring, `maxResults: 1`, then maps the
top `ScheduleSection[]` → `SelectedSection[]` via `parseSectionTimes`). Both
surfaces now run one solver.

### Dead code
`lib/course-planner/optimizer.ts` had **zero app importers** (verified by grep —
only its own test referenced it). Deleted it + `__tests__/optimizer.test.ts`.
`conflicts.ts` stays (re-exported) because the shared solver reuses its overlap
logic via `shared/schedule-conflicts.ts`.
